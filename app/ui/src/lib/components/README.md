# Arcane Modern components

Import `styles/tokens.css` and `styles/motion.css` once (already loaded by `app.css`). Components use Svelte 5 snippets and callback props, with no UI or animation dependencies.

- `Card`: named section; optional `tone="hero"` and `children` snippet.
- `Badge`: semantic `tone` and visible `label`. An estimated badge requires `estimated={{ reason: '…' }}` with a nonempty reason. Only debug mode shows the estimate marker and explanation; it opens on hover or focus and closes with Escape.
- `Tooltip`: unique `id`, `text` (or a `content` snippet for structured text such as lists), and `trigger` snippet receiving the ID to attach with `aria-describedby`. Triggers must be focusable. Content stays hoverable; keep essential actions outside tooltips.
- `ListRow`: one anchor with optional `selected`; its `children` snippet must contain presentation only, with no buttons, links, or focusable elements.
- `SpriteImage`: generated `SpriteRef`, local bridge-provided tile `sheetUrl`, `alt`, integer `scale` (1–16, default 4). Invalid rectangles, nonlocal URLs and load failures retain a labelled fallback. Source rects are bounded to 256×256 within a 16384×16384 atlas and the loaded tile must match the sprite width/height. Fitted trim offsets stay relative to the tile; atlas x/y are URL coordinates only. Rect-valid failures preserve frame size. The fixture tile is synthetic SVG, not extracted game art.
- `ItemTile`: an item `SpriteImage` plus the game's enchant pip (RarityIcon_1–4) anchored 1px from the bottom-right; `resolveSpriteUrl` resolves both the item and an individual tile from the extractor's `enchantPips.png` mapping. The pip count is the item's applied enchant count (`styles/enchant.ts`); missing, invalid or zero enchants show no pip. Pips are 16px on 40px+ tiles, 12px on 24–39px tiles and 8px below. Without pip art, one rarity-coloured gem per enchant keeps the labelled pip.
- `Banner`: visual presentation only, with generated `AlertKind`, event `id`, `title`, `context`, `onDismiss` and optional `celebrate` (default true). Optional `presentation` is `banner` (default) or compact `toast`; optional `view: AlertView | null` supplies screen-reader happened-at time and the View destination (falling back to `#/alerts` when no saved destination exists). Optional `portal: DungeonPortalSprite | null` shows a portal sprite at the left; null shows no icon and no placeholder. Banner loudness is a compact one-line strip; toast is a smaller card. Context and missing-relationship details render only in debug mode. No focus stealing, sound or notification. CSS provides one 650 ms shimmer, removed by reduced motion and paused when the document is hidden. Death always uses a sober panel without shimmer. Use `BannerHost` for announcements and deduplication.
- `BannerHost`: keep mounted for the display session; pass a `moment` or null and `onDismiss`. It renders an absolutely positioned overlay, out of document flow: place it in a `position: relative` container beside the scroll pane (Shell's `.content-pane`). Banners span the top (inset 20 px for the pane's scrollbar); toasts sit top-right. Alerts fly in and out (instant with reduced motion), and an outgoing alert is `inert`. Optional `presentation` and `view` pass through to Banner. Optional `client` enables the Key Popped portal sprite through `bridge/dungeon-portal.ts`; without it no icon renders. `sessionKey` resets its 256-ID announcement cache on namespace retirement; ordinary gaps retain it. Its one polite live region stays in the DOM even without a moment. A gap or previously announced ID clears the region; presentation-only updates to the current ID do not repeat its announcement. `onPauseChange(paused, hidden)` combines document visibility, pointer hover and focus within the moment; Shell owns the countdown. `showAlertsAction` supplies an adjacent Alerts link while a moment exists, retaining it while focused after Dismiss; positive `overflow` keeps it visible as "More Alerts". The idle host adds no link row. Shell passes `showAlertsAction` and `overflow`, so the Alerts link lives in the overlay and is the focus-return target. Optional `dismissFocusTarget: HTMLElement | null` supplies an external focus-return target instead. Explicit Dismiss transfers focus only when the removed moment owned focus. Legacy callers keep their original defaults and tab order. Deduplication covers announcements and shimmer, not the caller's event queue or alert policy.
- `EmptyState`: `heading`, optional debug-only `description`, optional `action` snippet and `state` (`empty`, `loading`, `unavailable`, `error`). Only loading marks the section busy; caller owns recovery and messaging.

Formatting and bag-tone helpers live in `../styles/`. `formatElapsed` subtracts decimal microsecond timestamps using BigInt. `bagTone` uses `is_white` first, then a caller-supplied reviewed `base_type` mapping; the default mapping is empty until assets join. It never infers a tier or sort rank from a name or numeric ID.

The development-only gallery is `tests/components/fixtures/ComponentPreview.svelte`, outside the production entry graph. It covers all components, bag tones, unknown/loading/error/estimated states, a disabled control, long text and a synthetic sprite. No production route or navigation entry is added. Mount this fixture in a development-only preview for browser QA.

Run the component suite with `npm.cmd --prefix app/ui run test:ui -- tests/components`, plus `run check`, `run check:tests`, `test` and `run build`. Browser QA still needs 100%/150% Windows scale, nearest-neighbor pixel edges, wrapping, tooltip placement near viewport edges, visible focus, reduced motion, and native screen-reader announcement behavior. jsdom cannot establish those visual results.
